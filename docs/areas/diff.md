## What it does

A pane between the chat and the side panel (which hides while it is open) shows an item's work as a diff to review and comment on. `GET /api/diff/<slug>?branch=B&scope=…` (read-only git, off the action mutex) answers through `BranchDiff`; `UnifiedDiff` parses git's text into files → hunks → lines, each line with old and new number, +/- stats per file.

**Scopes.** `branch` (default): merge-base → working tree, so uncommitted work shows. `commits`: merge-base → `HEAD`, what the PR shows, plus the branch's commits. `uncommitted`: `HEAD` → working tree. `pr`: the pull request as GitHub diffs it. `prompt` ("Since prompt", `PromptDiff`): what changed since one of the chat's prompts. Untracked non-ignored files join the two working-tree scopes as new files.

**Which branch.** The picker lists the item's linked branches that have a worktree (stack branches first, as `workspace` orders them), then linked branches with only a ref. Default: the most recently linked `issue/…` branch with a worktree, else the branch checked out where the chat runs (the live pane's `pane_current_path`, else `branch_diff::start_cwd`), else the first checkout, and only with no checkout at all the first ref-only branch. The picker sets the item's one selected branch (Workspace in [side-panel](side-panel.md)); the chat's checkout is marked `· chat`, a ref-only branch `· not checked out`.

**Base.** The gh-stack parent (local, else `origin/<parent>`) when the branch sits above another in its stack, else the merge-base with the first existing `GitRepo::TRUNK_REFS`, so a bottom branch diffs against trunk.

**Commits.** The `commits` scope returns `base..HEAD` oldest first (sha, short, subject, committer time, +/-; the newest 200, `commitCount` the total) and takes a contiguous run as `from`/`to` (one alone = that commit), diffed `from^..to` (a root commit against the empty tree); `range` carries full shas and a `label` (`abc1234` or `abc1234..def5678`). With a selection (Commits and PR) `messages` carries each selected commit's full message, author and date, oldest first.

**Branches without a checkout.** A ref-only branch (`refs/heads/<b>`, else `origin/<b>`) has `checkout: false`, `ref`, and the project root's `path`/`short`. It is read in the project root against its ref, resolved to a sha once per load, wherever a checkout uses `HEAD` (merge-base, commits, ranges, messages, `oldRev`, PR scope). Its `branch` scope is committed work only (`base..ref`, no uncommitted marks); Commits and PR work fully; Uncommitted and Since prompt are refused ("`<b>` is not checked out anywhere: …"). `oldRev`s, viewed marks and review anchors are shas and paths in the root's shared object store, so expanding, viewed tracking and drafts need no checkout.

**PR scope.** Which PR (`branch_diff`): a Review item's own (from its description, `branch_diff::review_pr`), else the selected branch's open PR from the PRs view's cache, else `gh pr view <branch> --repo …` (only `OPEN` counts). `branch_diff` runs one `git fetch origin +refs/pull/<n>/head:refs/quartermaster/pr/<n> +refs/heads/<base>:refs/remotes/origin/<base>` and diffs merge-base(`origin/<base>`, head) → head with `--inter-hunk-context=1` ([review](review.md)), so a stacked PR diffs against its parent as on GitHub. The payload is the Commits shape plus `base: {kind: "pr"}`, `pr: {repo, number, url, title, headSha, baseSha}` and `anchor` (the selected run's last commit, else `headSha`). A Review item with no linked branch diffs in the project's main checkout (`branch: null`, `checkout: false`) and opens on the PR scope by default. Other scopes answer `prAvailable` (a Review item, or the branch's PR in the cache), and only then does the bar show **PR**; its info line leads with a `repo#n` link.

**Since prompt.** The "before" state is qm's own snapshot, not Claude Code's file history (which misses changes made through Bash): `hooks/snapshot-worktree.sh` ([capture](capture.md)) records the worktree as a git tree at every prompt in `prompt-snapshots.jsonl`. `prompt_diff::snapshots_for` returns a session's snapshots oldest first, each labelled from the transcript: snapshot *i* owns the typed prompts (no interrupts, no sidechains) from its `at` up to the next snapshot's, both less 3 s, and takes the first (first line, 80 chars). A snapshot without its own prompt keeps `prompt: nil` and is known by time. `PromptDiff` serves `scope=prompt&prompt=<session>:<n>` (absent or not this session's: the last prompt) for the chat's current session: the live one whose claude descends from the tmux pane, else any live one, else the newest captured. It snapshots the `toplevel` now as the hook does and runs `git diff -M <prompt tree> <now tree>`; line addresses are the working tree's. Payload extras: `session`, `prompt`, `prompts` (newest first, `{id, prompt, at}` with `at` the transcript time, else the snapshot's), `base: {kind: "prompt", sha: <tree>}`. The bar's prompt picker reads relative time · first line.
- *Moved branches*: one `git log --walk-reflogs` over every `refs/heads/*` lists local branches whose newest reflog entry is after the snapshot's `at` (same second counts as before) as `movedBranches` (`{branch, commits}`, most recently moved first, `commits` = `rev-list --count from..tip`; `movedBranch` names the shown one, null for the chat's folder). A removed worktree's branch still shows. `&moved=<branch>` shows `from..tip`, `from` the newest entry at or before `at` (or, for a branch created since, its oldest), `base.kind: "prompt-branch"`; an unknown name falls back to the chat's folder.
- *Hiding a rebase*: the old head is HEAD's reflog entry at or before `at` (a moved branch: its `from`). Candidates: the gh-stack parent and `origin/<parent>`, then `TRUNK_REFS`, minus the branch and `origin/<branch>`; the first whose merge-base with old and new head differ (new descending from old) is the base that moved. The prompt tree is replayed onto it with `git merge-tree --write-tree --merge-base=<old base> <new base> <prompt tree>` and that tree diffed against now. Payload `rebase: {onto, commits, hidden}` only when a move is detected (`commits` = `rev-list --count <old base>..<new base>`); hiding is the default, `&rebase=show` turns it off.

**Stack layers.** For a branch in a gh-stack every scope but `uncommitted` carries (`StackLayers`) `layers` (bottom first: `{branch, n, add, del, commits}` from `parent..branch`, commits newest first, at most 200), `layerTrunk` and `fileLayers` (path → indexes of layers whose own diff touches it). Each commit has `alsoIn`: the trunk's or lowest lower layer's name whose `git cherry` side holds a patch-equivalent (a squash-merge or amended-parent leftover needing a restack). `&base=<branch>` (Branch and Commits) diffs a span: honoured only for a branch below in the same stack or the stack's trunk, from its merge-base — `base: {kind: "stack-span", branch, sha}`; anything else is ignored.

**Old side and context.** Every payload carries `oldRev`, the full sha of the old side as diffed: the base sha; a run's first parent (empty tree for a root); HEAD for `uncommitted`; the merge-base or run parent for `pr`; the snapshot tree, its rebase replay, or a moved branch's `<from>^{tree}` for `prompt`. A notice carries none. `GET /api/diff-file/<slug>?rev=SHA&path=PATH` (`FileAtRevision`, off the mutex) runs `git cat-file blob <rev>:<path>` in the project root → `{ok, lines, truncated}` (bytes scrubbed, ≤ 1 MB cut at a whole line, ≤ 20,000 lines) or `{ok: false, error}`.

**Committed vs uncommitted** (Branch scope, `UncommittedMarks`): two more diffs, base → HEAD and HEAD → working tree. An added line is uncommitted exactly when HEAD → working tree adds it; a removed line is committed when base → HEAD removes it, else mapped to its HEAD line (following `-M` renames) and uncommitted when HEAD → working tree removes that. Lines get `uncommitted: true` (context lines never); files `commitStatus` `committed`/`uncommitted`/`mixed`, from the lines when every change line could be told, else from which diffs touch the path. A line whose answer rests on a truncated or binary file stays unmarked, and a truncated branch file gets no line marks (its status still comes from the paths). Drawn as an amber gutter bar, an "uncommitted"/dashed "partly uncommitted" badge, and a legend in the bar.

**Viewed marks** (`ViewedMarks`): each file gets `digest` (status, both paths, every hunk header and line's kind + text — not the uncommitted marks) and `viewed`. The Viewed checkbox (a `role="checkbox"` button: a label inside `<summary>` would also fold the file) posts `diff-viewed` `{path, digest, viewed}` and flips at once (back on failure); a viewed file folds to its header and starts folded later, but opening it keeps it viewed. A mark shows in any scope whose diff of the file is the same.

**Branch stats** (`branch_stats`): `GET /api/branch-stats/<slug>?branch=B&refresh=1` (off the action mutex) measures the branch the pane would show, against the same base (`branch_diff::tip`: its checkout or, ref-only, the project root; head sha; base ref and merge-base sha). It runs the bundled branch-stats skill's script unchanged, `skills/branch-stats/scripts/branch-stats.sh <base ref> <branch>` from qm's own checkout, in that folder through the GUI's runner; an explicit base means it never fetches. The script's markdown is kept and parsed into `stats` (`branch`, `base`, `mergeBase`, `totals {files, add, del}`, `categories [{name, files, add, del, share}]`, `largest [{path, add, del}]`, `commits [{sha, subject, files, add, del, categories {name: {add, del}}}]`), `null` when it isn't the script's shape. The payload: `branch, base, head, mergeBase, computedAt, markdown, stats, commentary, commentaryAt, error, jobKey, commentaryRunning`. `branch-stats.json` keeps one entry per (repo root, branch), a hit only while head, merge base and base ref all match; a new answer or `refresh=1` replaces it, dropping its commentary. A failing or silent script answers `error` (branch and base still set) and is not cached. The `branch-stats-commentary` action (`{branch}`) runs a `gui_jobs` job keyed `jobKey` (`branch-stats:<root>:<branch>`, in the state's `jobs` while it runs): `env QM_SKIP=1 claude -p <prompt + markdown> --model haiku --tools "" --strict-mcp-config --no-session-persistence` writes two or three sentences on what stands out, stored as `commentary` only if the entry still has the shas it read. On the page (`gui/js/branch-stats.js`, `css/branch-stats.css`) the bar's 📊, shown when the diff has a branch, opens a modal: "Branch stats · <branch> vs <base>", head sha, merge base and when computed; big totals; a category share bar and legend; the commentary as a callout (or ✨ What stands out); Largest files and Per commit rows with +/− and a bar; ↻ refresh (`refresh=1`), ✨ and Close. ✨ reads "thinking…" while the job runs (`commentaryRunning`, or the key in the state's `jobs`) and "ask again" after; the job's finish (`jobFinished`) refetches an open modal for that branch. No `stats`: the markdown renders as issues do (`issueMarkdown()`, raw HTML escaped), under the commentary callout; `error` shows as is.

**The page** (`gui/js/diff.js`: pane, loading, bar, view modes; `diff-commits.js`: commit cache, scopes, prompts, commit list; `diff-nav.js`: file column, jump menu, viewed marks; `diff-file.js`: file rows, context expanding, highlighting). `d` (document key, never while a terminal has focus) or the header's **Diff** toggles the pane; `⇧D`, ⌘⇧⏎ outside the terminal or ⤢ Full fill the page (the terminal's own ⌘⇧⏎ maximize hides it). The bar: branch picker (or the stack strip, or under Since prompt the prompt picker, then the moved-branch picker **chat folder** / `branch · n commits`, then **hide rebase (n upstream commits)** when `rebase` is present); scope buttons Branch / Commits / Uncommitted / Since prompt / PR; view toggle Diff / Old / New; base or selected commits and totals; 📊 (branch stats, above), 🏁 (the branch's benchmark, when its project configures benchmarks, [benchmarks](benchmarks.md)), ↻. Under Commits the body starts with the commit list (scrolls past 30% of the height): click shows one commit, ⇧-click stretches a contiguous run, clicking the lone selected one or **Show all** returns to all. A single commit's message shows open, a run's in a folded `<details>`. One collapsible section per file (over 400 lines or under `__generated__/`: collapsed, built on first open); after a single selected commit's last file **Next commit →** selects the following one and scrolls to the top. Full mode over 720px adds a file column (`#diff-nav`: ✓, status, name, folder, amber dot, +/-, current file highlighted); otherwise **Jump to file…**; either opens the file and scrolls it to the top, and both and the bar say `N/M viewed`. Commit rows show short sha, subject and relative time; there is no non-contiguous selection. A run's folded messages keep their fold across re-renders; **Next commit →** is absent on the last commit, for a run and without a selection. `diffLineCode(file, line)` is the one place a line's text becomes HTML.
- *Stack strip* (`gui/js/diff-stack.js`): for an item with chains the branch select becomes the shown branch's chain, e.g. `main › ①–② merged › ③● › ④ name #PR › ⑤● top` (merged layers other than the shown one fold into one crumb — `①–③` when contiguous, `①③` when not; ◆ on the chat's layer, ⟳ on one behind its parent) or `main › fix-typo #42` for a loose branch. With several chains or extra branches (the chat's detached folder, an unlinked branch) a switcher `stack ▾ · +1 loose · +1 other` offers the rest; a branch no chain holds shows as a single crumb. A crumb click selects that branch (`setSelectedBranch`, so the checkout-needing scope fallback still applies). `⟳ n behind · restack` ends the strip and calls the `restack` action ([stacks](stacks.md)).
- *Layered commit list* (Commits and PR with `layers`): top layer first, a header per layer (number, name, PR chip, +/−, n commits, ⟳) over its commits. Layers the loaded diff covers list the diff's own commits (pickable as usual); others list `layers[].commits`, a click selecting that layer with that commit. Over 10 commits shows the newest 6 (plus any selected) and "N more commits — show", unfolded per slug|branch for the page's life. Header click selects the branch; ⇧-click on a second header spans from the last header clicked (while shown, else the shown layer), the upper one becoming the selection (`base` = the lower one's parent, the trunk for the bottom; Commits only, never PR). `alsoIn` commits are dimmed and tagged "also in ②", never hidden. File headers get layer circles from `fileLayers`, coloured by PR state.
- *Expanding context*: a modified or renamed text file with hunks gets expander rows (`tr.d-expand`) before, between and after hunks; ≤ 20 hidden lines is one "⇕ N unchanged lines", longer runs offer ↓ 20, ↑ 20 and ⇕ all. The first expand fetches the old file at `oldRev` (`f.oldPath` for a rename); only then is its length known, so the trailing expander vanishes once exhausted. Expanded lines are context lines (`d-expanded`, old `k`, new `k + delta` from the neighbouring hunk), commentable like any other with their draft rows; in the PR scope they are `gh: false` (GitHub takes comments only inside the PR's hunks).
- *View modes*: Diff, Old (context + removed) and New (context + added), per tab (not per chat) in `sessionStorage` `qm-diff-view`. A single-side mode hides the other side's lines, its number and sign columns, and swaps the changed rows' tint for a bar on the right edge of the shown number cell (green in New, red in Old; the amber uncommitted bar moves to its left edge). A switch only toggles `d-only-old`/`d-only-new` on `#diff-body`; rows hanging off a line carry `data-side` (`markDiffRowSides`) so they hide with it; revealing a hidden draft from the tray switches back to Diff.
- *Syntax highlighting*: highlight.js (pinned, SRI, in `page.html`), language by name or extension (`diffLanguage`: a few extras like `Gemfile`, `.erb`, `.tsx` mapped, the rest tried as aliases). Each hunk side (old: context + removed, new: context + added) is highlighted as one piece so multi-line strings stay coloured, then cut back into lines (`splitHighlightedLines`); on context lines the new side wins. Colours are `--syn-*` tokens, light and dark, chosen to read on the add/del tints.
- *Switching commits fast*: during a load the old diff stays, dimmed (`d-stale` after 0.2 s), and only the bar redraws. Selected-commit diffs (`diffKeepable`) are kept in `diffCache` (8, one minute, by `diffKey`) and the next single commit is prefetched (`prefetchNextDiff`, no `fresh=1`, no threads); an entry holds its request, so a click during a prefetch waits on that same request.

## Rules

- A branch outside the picker's list is refused; `from`/`to` must be 4-64 hex digits resolving to commits in `base..HEAD` with `from` an ancestor of `to`, so no other ref reaches git.
- A ref-only branch is never read from the project root's working tree or index — those are another branch's.
- The default branch pick never prefers a ref-only branch over a checkout.
- `branch_diff::require_checkout` guards the prompt scope too; `PromptDiff` would otherwise answer from the chat's folder.
- Under `checkout: false` Uncommitted and Since prompt are disabled with a title saying why, picking such a branch under either falls back to Branch, and the uncommitted legend never shows.
- Untracked files are capped at 200 files of ≤ 1 MB each; past 20,000 diff lines files keep their stats but lose their lines (`truncated`).
- The PR fetch is the diff pane's only network/ref side effect; a PR whose repo isn't the project's origin is refused.
- `PrMemo` (per GUI process, in memory) remembers lookups and fetches for 60 s, reused only while `refs/quartermaster/pr/<n>` still holds the head and its merge-base is in the checkout; a slower lookup never overwrites a fresher one.
- `fresh=1` bypasses the memo: sent on ↻, a turn's end and arriving at the PR scope, never for a commit or branch change within it. The CLI and review posting never use the memo, so a post never acts on a stale head.
- `prAvailable` never calls gh: loading a diff never waits on GitHub.
- Branch stats never fetch and never use a model for the numbers; the haiku commentary runs only on a click, as a background job, never under the action mutex.
- `branch-stats.json` is a real cache: an unreadable or foreign-version file reads as empty, writes go to a temp file then rename.
- The branch-stats script's markdown is `branch_stats`'s parser input: a change to its output format changes the parser in the same commit (`tests/gui.rs` runs the real script and parses it).
- The stack span base is ignored by the PR scope (GitHub diffs a PR against its own base); the layers a loaded span covers are read from the answer (`base.kind == "stack-span"`), not the choice.
- Only the selected branch's (or span's) diff body is built — never the whole stack.
- Per-layer git answers are cached on the tip shas (`gh_stack`) and tips resolve via `gh_stack::RefTips`, so a reload with unchanged refs runs no per-layer git.
- Layer `add`/`del` come from `git diff --numstat --no-renames parent...branch` (three dots), so a parent that moved on doesn't show reversed.
- A multi-commit layer squashed into one commit matches none of its commits in `alsoIn`: patch-ids are per commit.
- The span base is part of `diffKey` and sent as `base=` only under Branch and Commits (`diffSpanBase`); Branch ↔ Commits and Show all keep it, any branch pick drops it.
- Each strip `› crumb` is one unbreakable step and the strip wraps, so a narrow pane never scrolls sideways.
- Snapshot windows never overlap, so a prompt-less snapshot never takes its neighbour's label.
- The now-snapshot uses a temp index copy under `GIT_INDEX_FILE`; the real index stays byte-identical, the only side effect is loose objects.
- Since prompt shows nothing as a `notice` beside empty `files`, never an error, so the picker stays: no session, no snapshots, a pruned tree ("that prompt's snapshot is gone"), a vanished worktree.
- Picking the newest prompt clears `diffChoice[slug].prompt`, so the default keeps following new prompts; an older pick, `moved` and `rebase: "show"` are kept per item and are part of `diffKey`.
- A rebase candidate whose merge-base *is* the new head is skipped: the branch's own commits landed there and say nothing about upstream.
- `merge-tree` accepts the snapshot tree as a side only with `--merge-base`; it writes objects only, never a ref, index or worktree. A conflicting replay falls back to the plain diff with `rebaseNotice`, never conflict markers.
- `FileAtRevision`: `rev` must be 4-64 hex and `<rev>:<path>` is one argument, so nothing else reaches git; it runs in the project root because worktrees and prompt snapshots share its object store.
- Expander spans come from the hunks (`diffHunkSpan`), never by changing `f.hunks`: the highlight cache and viewed digests are keyed on them.
- Expander rows are their own table rows so hunk headers stay the separators and a click never folds the file's `<details>`; a ⇧-click range can't span one.
- A file the line limit cut short has no trailing expander; nothing past the fetched lines is offered.
- Fetched old files are kept per `oldRev + "\0" + oldPath` (`diffContextFiles`, 50) until ↻, another chat or reopening — not at a turn's end, a file at a sha can't change.
- What is expanded is kept as old-line intervals per `oldRev|oldPath|path` (`diffExpanded`, 200 files) and re-applied by `fillRows`, refetching a dropped file.
- An expanded line's highlighting is one pass over the whole fetched file, none past 10,000 lines or with a line over 1,000 characters.
- A line stays plain escaped text when highlight.js didn't load, the language is unknown, a side has a line over 1,000 characters, or highlighting throws.
- Highlights are cached per file object and across loads by file digest (`diffHighlightsByDigest`, 300), so a turn-end reload re-colours only changed files.
- The pane refetches on open, chat change, a chat turn's end and ↻ — never on a state refresh, which also leaves its DOM alone (a rebuild would reset folds and close an open picker).
- `diffCache` is dropped on ↻, a turn's end, another chat and pane open; reloading the diff already shown skips its entry.
- The commit selection lives in the page's per-item choice (memory only), dropped when scope or branch changes; a selected sha gone from the branch offers **Show all commits**.
- Open/closed is per chat (`qm-side-panes`, adopted by `adoptSidePane`), Full per tab (`qm-diff-max`), both in `sessionStorage`.
- View-mode switches never refetch or rebuild rows; CSS does it. Hunk headers, the tray and file stats are unaffected.
- The viewed digest leaves out uncommitted marks, so committing a file doesn't unview it; an agent's edit changes the digest, so it reads unviewed again.
- Re-rendering the same diff keeps every file folded or opened as the user left it.
- Resolving an item, by any path (`work_item::update_state`), drops its viewed file: a reopened item's review starts over.

## Data

- `prompt-snapshots.jsonl`: `{v: 1, session_id, cwd, toplevel, tree, at}` per prompt, append-only; read whole, torn lines, bad trees or unparsable `at` skipped.
- `viewed/<slug>.json`: `{v: 1, marks: {path: [digest, …]}}`, newest last, newest 6 per path, the 2000 most recently marked paths; flocked, renamed into place, removed once empty.
- `refs/quartermaster/pr/<n>` in the project repo: the fetched PR head.

## Known limits

- Prompt-snapshot trees are unreferenced objects; `git gc` prunes them after ~2 weeks.
- A branch without a reflog never shows as moved; uncommitted work in other worktrees is out of reach of Since prompt.
- `content-visibility: auto` on file bodies was tried: under 10% layout saving, and it breaks the kept scroll position.
